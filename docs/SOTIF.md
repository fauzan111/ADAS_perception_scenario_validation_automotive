# SOTIF failure tables

Generated by `make sotif sotif-edge` (`src/adas_validation/sotif.py`). Every collision is
attributed by counterfactual reruns that remove one limitation at a time. The cause is the
first step that removes the collision:

1. **detection**: perfect detection (any range, no misses, no ghosts), same seed and the same
   position-noise draws as the failed run
2. **noise**: no position noise either (oracle perception; latency and 3-of-5 track
   confirmation kept)
3. **friction**: dry-road braking (9 m/s^2) instead of wet (6.5 m/s^2), rain only
4. **reaction**: no sensor latency, tracks confirmed on their first detection
5. **decision**: the AEB knows the lead's true deceleration (the tracker estimates none, so the
   AEB otherwise assumes a braking lead keeps its speed)
6. **design_limit**: nothing above removes it: this AEB, which brakes only for objects
   predicted in its path, collides even with ideal inputs

Mitigations are proposals, not tested here (except where the sweeps bound a speed or gap).
